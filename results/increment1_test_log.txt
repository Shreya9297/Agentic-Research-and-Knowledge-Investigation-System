Answer: The root cause of Excessive Agency in LLM applications is typically one or more of the following:

• Excessive functionality: Tools provide functions beyond what is needed, old development tools remain accessible, or open-ended tools fail to properly filter input commands.
• Excessive permissions: Tools hold unnecessary permissions on downstream systems (e.g., write/delete access when only read is required) or use generic high-privileged identities rather than user-scoped permissions.
• Excessive autonomy: An LLM-based application or tool fails to independently verify and approve high-impact actions.

Damaging actions are commonly triggered by:
• Hallucination or confabulation caused by poorly engineered benign prompts or a poorly performing/misaligned model.
• Direct or indirect prompt injection originating from a malicious user, an earlier invocation of a compromised tool, or a compromised peer agent in multi-agent environments.

Answer: Prompt injection acts as an input-side compromise (via direct user prompts or indirect external content like web pages, documents, or tool responses) that manipulates LLM output. When an LLM has excessive functionality, permissions, or autonomy, this manipulated output triggers damaging actions outside the chat window, such as unauthorized tool invocation, exfiltration, or modifying configurations under elevated privileges.

For prompt injection, OWASP recommends architectural defense-in-depth since prevention cannot be reliably guaranteed. Strategies include:
• Assuming instruction boundaries will be bypassed and constraining what the model is permitted to do and what outputs can reach.
• Constraining the model's role and capabilities in system prompts using declarative allow/deny statements.
• Applying least-privilege and capability-budgeting controls.
• Avoiding the "lethal trifecta" by ensuring an agent does not simultaneously access private data, ingest untrusted content, and communicate externally.

Answer: The assumption in the question is incorrect. OWASP does not state that unbounded consumption only affects image generation models and not text models.

According to the evidence, unbounded consumption applies to LLM applications in general when they allow excessive and uncontrolled inferences, enabling attackers to disrupt service availability, inflict unsustainable financial costs, or steal intellectual property through model cloning.

Furthermore, the evidence notes that this risk is compounded by factors involving text and multimodal processing alike, including the growing adoption of extended-thinking and reasoning models with large or insufficiently constrained output budgets, cloud and pay-per-token environments, multimodal models that increase per-request compute costs, and agentic architectures or tool-use protocols (such as MCP) that amplify single requests into cascading operations.
